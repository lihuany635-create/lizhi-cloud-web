# GridCraft Windows v0.4｜打開代理即自動連線（候選）

日期：2026-11-18。狀態：候選開發，**未取代 Windows v0.3、未修改原 Site v30／Edge v6**。

## 主要改動

- Windows v0.4 啟動時，沿用既有 Windows 使用者帳號安全保存的配對資料；若上次未手動停止遠端，自動啟動遠端 HTTPS 代理，無需重新輸入 MCP 配對碼或重按「開始遠端」。
- 已設定 GridCraft.exe 時，啟動代理會先檢查既有 GridCraft；若未開啟則自動啟動，不會重複開第二份。
- 本機明確授權「已儲存」工作簿時，只把**標準化本機絕對檔案路徑 SHA-256** 記在目前 Windows 使用者本機 settings.json；不把路徑、Token、檔案內容送到 MCP／Supabase。再次啟動僅對實際存在且本機 document.inspect 路徑**完全符合**的檔案恢復讀取授權，不能靠同名 Book1 或暫態 doc UID 自動授權。工作簿名稱相同、另存為其他路徑或路徑不存在都不應恢復。
- 在執行每一項讀取或 P4 工作前，重新檢查目前工作簿的實際身分。當檔案關閉、替換或路徑變更時，撤銷該次本機授權；雲端完全無法自行提升授權。
- 加入明確的「記住本機 P4 寫入允許」勾選，**預設關閉**；本人第一次在 Windows 確認後，可在下次啟動自動恢復本機寫入開關，但**原 Private Site 每一筆寫入的預覽與本人單次確認仍然必須遵守**。本機仍可隨時按停用或停止遠端。
- 未儲存的 Book1 沒有持久檔案身分，因此**只支援目前工作階段人工授權**。第一次請先存成測試副本再授權，後續才可全自動復原。
- 原 P3/P4 MCP 名稱、Edge、Site、Supabase、Secrets、備份、版本檢查、單次確認及本人驗證沒有修改。

## 驗收

[Windows v0.4 CI](https://github.com/lihuany635-create/lizhi-cloud-web/actions/runs/44308530607)：10 項新安全／自動啟動測試、P3/P4 原測試，Windows EXE 打包與自檢（以 Actions 的最終結果為準）。真實本人 Windows v0.4 自動登入、真正工作簿路徑、跨重啟與寫入均 **NOT_TESTED**。

## 正式啟用前

請保持原 v0.3 正常使用，不要自動替換程式。候選 ZIP 發布後本人可先備份現有 Windows settings.json，停止 v0.3、開啟 v0.4，將現有 Book1 存成一份實際測試副本，再「授權目前工作簿」**一次**；下次重新開啟 v0.4 將自動恢復相同已儲存檔案的連線與授權。寫入仍需要當次原私人 Site 確認；不自動執行任何 P4 commit。

如需求是連「每筆寫入到 Site 確認」也不想做，須先設計另一種安全授權政策，不能在本次啟動自動連線改動中偷偷移除雙重確認。
