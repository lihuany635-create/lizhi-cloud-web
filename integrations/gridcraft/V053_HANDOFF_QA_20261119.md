## 難點與安全限制

- 第一次從 **v0.5.2 或更舊** 換到 v0.5.3 時，舊程式沒有 Local Quit 事件及互斥鎖，不能安全保證自動通知它退出。若舊實例仍運作，新版只喚出舊視窗並停止覆蓋，使用者須**先正常關閉一次舊版**；自 v0.5.3 起才有具名事件自我更新。這是避免正在進行的 P4 寫入被強制中止所必需，不能宣稱第一次升級全自動。
- 收據壞行會保存 `p4-write-receipts.corrupt-YYYYMMDD-HHMMSS.jsonl` 和有效行新檔，但留下 `p4-write-receipts.needs-review` 標記；P3 照常，P4 Gate OFF。需本人檢查損壞原因與持久 SHA256 防重放索引後，才可移除標記恢復 P4，**不會自動清除安全封鎖**。
- `agent.log` 使用 RotatingFileHandler 1 MiB × 3 個輪替檔案，只保存狀態變化及代碼（允許 request_id 和 backup_id）；不保存儲存格值、配對碼、token、完整工作簿名稱或路徑。
- 新 Edge 功能僅由受驗證的 **固定 HTTPS 回應** 宣告 `heartbeatMerged` / `longPoll` 才開啟。未發布 Edge v7；原 v6 不回旗標，Windows 保持 heartbeat 和短輪詢。
- 備份輪替是依本人要求放寬原「永不刪備份」限制：最少保留最新20份，空間不足先刪最舊；是否滿足稽核長期保留政策仍需本人決定。

## 手動驗收清單（本人 Windows，均待驗收）

- [ ] **單一實例**：雙擊新版 EXE 兩次，只剩一個代理視窗；第二次應喚回第一個。
- [ ] **停止與重連**：按「停止連線」後立即按「重新連線」，回 MCP READY，沒有兩個輪詢執行緒。
- [ ] **收據壞行**：在測試用備份資料夾的收據最後附加無效 JSON 行後開新版，能進行 P3 工作簿讀取、出現 corrupt-時間戳歸檔，P4 工具回 P4_GATE_OFF；完成後保留 marker 供本人檢查，勿隨便覆蓋真實帳本。
- [ ] **自我更新**：安裝版 v0.5.3+ 舊程序收到 Local Quit 事件後退出，新二進位取代安裝版，HKCU Run 已存在時指向安裝路徑。從 v0.5.2 升級時須先正常關閉一次舊版。
- [ ] **網路斷接**：斷網一段時間再接通，代理自動重新連線；觀察錯誤退避及正常輪詢間隔。
- [ ] **隱私日誌**：打開 `%LOCALAPPDATA%\Lizhi\GridCraftAgent\agent.log` 及 .1/.2/.3，確認沒有儲存格內容、token、配對碼、裝置憑證、工作簿完整路徑。
- [ ] **不改使用者資料**：換 Excel 時 list_workbooks 自動更新；只有在本人明確授權的測試副本上執行 P4，備份與讀回 PASS。
- [ ] **原 Site／舊 Edge**：不更新 Edge 的情況下，原 v31 read／write 完全可用，無額外確認頁。
