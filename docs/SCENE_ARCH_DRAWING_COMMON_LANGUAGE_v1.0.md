# 立之雲端庫｜建築場景圖說共通語言與 AI 交付約定 v1.0

- 建立日期：2026-10-26
- 適用：製作工作台「場景模型製作」中所有住宅、學校、室內外建築場景；目前先以《現實遊戲》EP02 的 RG-GAME-HOUSE 哈德斯家驗證。
- 性質：**團隊作業／溝通規範草案**。本次使用者要求先建立共通語言，再正式登載各張圖說需求；本文件規則已整理，不表示作者逐條正式驗收或已繪製各圖。
- 目的：同一名詞、圖號、方位、尺寸、來源、圖面狀態與交付準則，避免多個 AI 重新解釋或誤用舊稿。

## 1｜核心名詞（不可互換）

| 名詞 | 定義 | 常見誤用禁止 |
|---|---|---|
| 圖說 | 同一場景中成套圖面、尺寸、符號、材料與文字規格的總和 | 不得把一張方塊圖稱為「完整圖說」 |
| 圖面 | 一張具有圖名、圖號、版本及用途的可讀圖紙或圖檔 | 單張圖不代表一套已核定 |
| 基地配置圖／Site Plan | 建築在基地中的位置、朝向、道路、庭院、車道、停車位、鄰棟關係 | 不等於一樓平面圖 |
| 建築平面圖／Floor Plan | 各樓層水平剖切後的牆、柱、門窗、樓梯、空間、尺寸與索引 | 不是無尺寸的彩色房塊示意 |
| 屋頂平面圖／Roof Plan | 從上方確認屋頂輪廓、坡向、突出物與樓層對應 | 不等於二樓平面圖 |
| 建築立面圖／Elevation | 建築外部單方向正投影；核對門窗高度、外形、材料與屋頂 | 不等於 3D 透視效果圖 |
| 建築剖面圖／Section | 由指定剖切線做垂直剖面，核對各樓層、屋頂、梯段與高度 | 無剖切位置不可聲稱能核對所有結構 |
| 建築詳圖／Detail | 對局部放大並註明構件、收邊、標註及連接條件 | 無尺寸的特寫圖只屬參考 |
| 家具配置圖／Furniture Plan | 平面中固定家具、可移動家具、活動及通行淨空 | 不能由家具圖取代隔間平面 |
| 室內立面圖／Interior Elevation | 從室內看向某面牆的正投影，核對櫃體、門窗、牆面配置 | 非建築物外觀立面 |
| 結構配置概念圖／Structural Concept | 模擬柱、梁、樓板、樓梯孔洞與受力路徑合理關係 | 動畫概念圖不等於結構計算或專業簽證 |
| MEP／設備配置圖 | 電氣、照明、插座、給排水與通風等設備的功能配置 | 可見燈具不得直接當作電路已完成 |
| 門窗表／Schedule | 以 D/W 編碼管理門窗的尺寸、位置、型式、開向和材質 | 不可讓不同樓層同一 D/W 編號指涉不同物件 |
| 3D 灰模／Blockout | 按核定圖說構築的低細節可量測三維場景 | 草圖、透視圖與圖片不代表可操作 3D 模型 |
| 透視圖／Render、動畫鏡位圖 | 表達視覺及攝影效果；有來源模型與相機參數時可驗證 | 不能取代尺寸圖、立面圖與剖面圖 |

## 2｜專業圖號與編碼約定
- `A` = Architectural：建築基地、平面、立面、剖面、詳圖。
- `I` = Interior：家具、室內立面、裝修。
- `S` = Structural concept：結構幾何概念及樓板孔洞、柱梁位置（非工程計算簽證）。
- `E` = Electrical：室內燈具／插座／基本照明配置。
- `P` = Plumbing：給排水、衛浴、濕區概念配置。
- `V` = Visual/Animation：攝影機、人物動線、窗外視錐、日夜狀態。
- `M` = Model：3D 模型物件對照、原點、版本、資產 ID。
- 採 `專業碼-三碼流水號`，例 `A-101` 一樓平面，`A-301` 建築剖面一，`I-101` 一樓家具，`V-002` 主角窗景。**圖號是本工作台的約定，非宣稱採用政府或 CNS 的官方圖號分類。**
- 場景標識 `RG-GAME-HOUSE`、房間編碼延續原案 `H1-01`～`H1-09`、`H2-01`～`H2-06`；不重命名既有來源以防斷鏈。新增房間時另分配新 ID。
- 門 `D-01`、窗 `W-01`、固定家具 `F-001`、劇情可互動道具 `PROP-001`，在圖面和模型節點保持一致；正式採用時先檢查與既有資產編號是否衝突。
- 每個成果檔名建議：`RG-GAME-HOUSE_A-101_R00_20261026.pdf`；具可編輯來源時另存 CAD/SVG，圖號、版次、檔案內容必須一致。

## 3｜方向、尺寸和圖面交互語法
- 首次出圖需共同定義基地北向及建築入口；「正立面」指向**主入口所在的立面**，不能誤當固定的南立面。
- **哈德斯家目前南側住宅街與東南車位只是未核定座向假設。** 每張平面均顯示北箭頭；每張立面註明視線由外向內的方向。
- 平面圖中，尺寸一律標註 `mm`；標高用 `m`，例如暫定 `1F FFL±0.000`、`2F FFL+3.000`；前述 2F 標高只屬前期建議，不是已核定樓高。
- `FFL` = 完成地坪標高；`CL` = 天花高度；`W`、`D` 等門窗ID；`X/Y` = 平面世界軸，`Z` = 垂直軸。3D 模型採 m 實際單位，輸出時與圖面 mm 明確換算。
- **外包尺寸**是外牆外緣至外緣，**淨尺寸**是室內完成面到完成面，**中心線尺寸**是軸線到軸線，**淨寬**是通行可用寬度；未標清種類的數字不得自動混用。
- 需標比例、圖面出圖大小（或註明不按比例）、房間 ID、門窗 ID、主尺寸與局部尺寸、截面標籤及引用圖號。軟體畫面縮放不代表紙本比例。
- 面積 `m²`；避免把 9×8m 外包輪廓 72m² 當作每個空間可分配的淨面積。標註「概算」或「實測」。
- 重要門、窗、樓梯的平面位置須與四向立面、剖面、屋頂圖及 GLB 相互對上。
- 尺寸、軸網、圖例、門窗清單與模型一致性優先於裝飾；絕不可憑想像標為「已量測」。

## 4｜同一場景的設計事實分層
每一項有意義的設定須記錄：
- `STORY`：原作正文或正式採用分鏡可證明的劇情事實，需指出章節／鏡號。
- `USER`：使用者親自核定的方向／尺寸／空間配置，需指出核定對話或工作台決議。
- `PROPOSAL`：AI 或設計師提案，**不得**自動改為 `USER`。
- `MEASURED`：已實際讀取具體模型/圖面後得到的量測或檢查值，應附模型 SHA、工具、座標與結果。
哈德斯家目前：`USER` 普通家庭住宅；`PROPOSAL` 9×8m、南側臨街、東南車位、U 型樓梯、附加房間；`STORY` 遊戲臥室、學生身份資料、上學／黑色轎車敘事。

## 5｜製圖狀態與核定權
- `DRAFT` 草稿：可討論，未完成尺寸/跨圖校對。
- `REVIEW` 待審：尺寸、對照及交付齊備，提交作者核對。
- `APPROVED` 作者核定：由使用者明確同意具體版次與適用範圍後登記；不由 AI 自行升級。
- `BLOCKED` 受阻：缺少關鍵來源、互相矛盾或技術無法執行。
- `SUPERSEDED` 被新版本替代：舊圖保留、標明新圖號和版次；不能刪掉歷史。
獨立標記 `NOT_MODELED`、`MODELED_CANDIDATE`、`MODEL_VERIFIED`，**圖面核定不等於 3D 模型完成**；任務 PASS 需具體證據，且不自動代表作者採用。

## 6｜圖紙圖框與共同交付欄位
所有圖面至少具備：作品／場景 ID、圖號、圖名、出圖日期、版次、製作者、狀態、比例／「示意不按比例」、圖面單位、方位或視向、來源依據、仍待決事項、下一步、相關圖號。畫面有紅線變更時新增版次與變更摘要。
每份交付至少含：
1. **可檢閱預覽**：清晰 PNG 或 PDF（圖面文字、尺寸可讀）；SVG 作可縮放的預覽但不等於上傳至工作台私人圖片原檔。
2. **可編輯來源**：使用 CAD 時給 DXF/DWG 或其受支援原始格式；初期向量示意則保留 SVG 源。未實際生成 CAD 禁止宣稱有 CAD 檔。
3. **交付索引**：位置/URL、SHA（若取得）、圖號、版次、狀態、內容摘要、對照目標。
4. **檢查紀錄**：記錄層間樓梯吻合、動線、窗景、剖面和立面尺寸是否一致；若未檢查明確標 `NOT_TESTED`。
5. **工作台記錄**：登記為「場景模型製作」指定 S01/S02/S04 的成果與待辦；成功存專案成果引用不等於「圖片」私有區已保存原圖。

## 7｜AI 接力時固定說法
- 「已畫出方塊配置」≠「建築平面圖尺寸確認」；
- 「已登記成果連結」≠「已在圖片儲存區保存原圖」；
- 「原作描述」≠「房間格局已定案」；
- 「草稿已更新」≠「GLB 已重製」；
- 「立面完成」不意味剖面、結構與門窗已一致。
- 每次接手先讀**共通語言規範**與該場景**圖說清單**、最新作者核定及被取代版次，再動手；由上一任 AI 的敘述不能自行推定作者已採用。

## 8｜與場景模型 12 階段串接
- S01：劇情用途、USER/STORY/PROPOSAL 來源與必要鏡頭。
- S02：必要圖說與空間／資產清單，附 P0/P1/P2。
- S03：圖片／尺寸／外觀參考資料與來源驗證。
- S04：完成 A／I／S／V 互相校對，作者過「關卡 A」後才將其作為灰模基礎。
- S05～S10：依核定的空間、物件與材質建模，持續保留對應圖號。
- S11：從視線、動線、動作、攝影機與效能實測；S12：版本及驗收。
