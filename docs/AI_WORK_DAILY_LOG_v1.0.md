## 一、記錄原則

1. **每天、每項任務分開記錄**：同一天可以有多位 AI、不同專案或不同任務；每一筆都標示日期、執行者及專案，不得混寫。
2. **不以宣稱代替事實**：把「已計畫、已下指令、實際執行、已讀回驗證、經負責人驗收」分開。沒有實測證據時用 `NOT_TESTED`；不將檔案建立誤稱為網頁部署完成。
3. **工作台紀錄為準**：本文件是供人閱讀的日誌格式與彙整入口。各專案原有的不可覆寫工作紀錄、任務、證據及版本是正式事實來源；新增日誌時應優先用該專案提供的工作紀錄工具保存並讀回，避免建立互相矛盾的第二套進度。
4. **不虛構工時**：開始與結束時間、耗時、執行者身分未能查證就留空或寫「未記錄」，不得根據對話時間推算工作時數。
5. **保護資料**：不得寫入 Token、密碼、私人螢幕內容、完整金融帳號或其他不必要的個資；提供經授權且可核實的文件、commit、job 或測試結果連結即可。
6. **留交接**：每筆日誌至少寫明「成果／驗證／未完成／下一步／需不需要負責人操作」。未同步到工作台時需明標「未同步」。
7. **不表示已自動化**：建立本文件不會自動從聊天、其他 AI 或各工作台抓取資料；需在相應工具具有授權、實際寫入並讀回後，才能聲稱有新日誌。

## 二、每日工作紀錄模板

以下模板請複製成一筆新紀錄。真正記入工作台時，優先映射為該專案既有欄位。

```yaml
日期: YYYY-MM-DD
時區: Asia/Taipei
執行者: "<AI 名稱或實際操作人；未知寫未記錄>"
專案: "<明確專案名稱>"
project_id: "<穩定 ID>"
task_id: "<任務 ID；無則寫未建立>"
工作項目: "<當日做什麼>"
開始時間: "<有實際紀錄才填；否則未記錄>"
結束時間: "<有實際紀錄才填；否則未記錄>"
工時: "<有證據才填；否則未記錄>"
執行環境: "<如 GitHub、工作台 MCP、手機；未驗證就標示>"
當日成果:
  - "<實際完成的工作，不把計畫寫成成果>"
驗證狀態: "PLANNED|IN_PROGRESS|PASS|FAIL|BLOCKED|NOT_TESTED"
驗證方法: "<實際查核方法，沒有則寫未驗證>"
證據:
  - "<可重查的檔案版本、commit、job、測試或工作台紀錄 ID>"
仍未驗證:
  - "<沒有就寫無>"
問題與阻礙:
  - "<目前有效問題，沒有就寫無>"
下一步: "<下一項可執行工作>"
需負責人操作: "<是／否；若是，說明具體事項>"
工作台同步: "<已寫入並讀回／未同步>"
```

## 三、查閱方式

- **看今天做了什麼**：按日期搜尋對應工作紀錄，逐筆核對專案、執行者與證據。
- **想交接給下一位 AI**：先讀《AI 員工守則》，再讀目標專案最新工作台狀態、版本、未結事項及本日誌；不要只憑日誌文字直接修改其他專案。
- **想看工作量／工時**：只有實際保存起訖時間或工時的紀錄能用於統計，否則標示資料不足，不計為零工時。
- **想修改舊紀錄**：不抹除原工作台紀錄；用新紀錄註明更正原因、被更正紀錄的 ID 及佐證。
