## 產品定位

- 要解決的問題：工作上的公文（收文＋發文）集中放置、記錄處理狀態、能搜尋篩選，且欄位由 AI 自動填。
- 主要使用者：只有使用者本人（沿用 `lizhi_web_is_allowed()` 核准帳號）。
- 平台：立之雲端庫網站（手機與電腦瀏覽器）。
- 與既有系統關係：**擴充既有圖書館 `?open=library`**，不另建網站。圖書館上方新增「館藏／工作專區」切換；工作專區第一個功能是「公文」。
- 第一版交付：可操作的工作專區頁面＋資料表＋每晚 AI 整理流程。

## 使用流程

1. 使用者把公文 PDF／圖片丟進 Google Drive：
   - `立之圖書館｜公文/收文`（`1n5pHpLhanjc6b8UnQwz4lzKRtqFkI4DY`）
   - `立之圖書館｜公文/發文`（`1Bt9RdL5EgE0mZGwcuw-tj3mm7qGYAYXa`）
   - 根資料夾：`1XTIZa7LRAAsd1aKSqYGS_BOjQxZ9esns`
2. 每晚 21:52 的圖書館整理任務一併處理：用 Drive 連接器列出兩個資料夾，新檔案登記成一筆公文（`ai_status = inbox`），讀檔內容後填欄位（`ai_status = filled`）。
3. 使用者在網站工作專區看列表、搜尋／篩選、修改欄位、切換處理狀態（待辦／辦理中／已結案）、點連結開 Drive 原檔。
4. 也可在網頁「＋手動登記」填欄位並貼 Drive 連結（例如臨時記一筆）。
5. 想馬上處理時，對 Claude 說「幫我整理公文」。

## 第一版驗收

| 編號 | 操作 | 期望 |
|---|---|---|
| W1 | 圖書館上方點「工作專區」 | 顯示公文頁；點「館藏」回原本圖書館，原功能不變 |
| W2 | 丟一份收文 PDF 進「收文」資料夾，說「幫我整理公文」 | 出現一筆收文，文號、機關、日期、主旨、期限由 AI 填好；讀不出的欄位留空並註明 |
| W3 | 搜尋文號片段或機關名稱、切狀態篩選 | 只顯示符合的公文 |
| W4 | 修改主旨、把狀態改成已結案、重新整理 | 修改保存且讀回一致 |
| W5 | 同一 Drive 檔案再次整理 | 不重複登記（drive_file_id 唯一） |
| W6 | 另一帳號或未登入 | 讀不到任何公文 |

需本人確認的高風險操作：套用 migration 到正式 Supabase、合併 PR／部署。
回退：還原前端檔案；資料表是新表，不動既有圖書館資料，可保留或 `drop table`（須本人同意）。
