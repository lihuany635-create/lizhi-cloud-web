# 場景模型製作｜標準流程與 AI 接力手冊 v1.0
更新：2026-10-26｜狀態：流程文件（不代表任何模型已製作或通過驗收）
所屬：立之雲端庫製作工作台／場景模型製作
專案 ID：134dad4c-c9d3-48b3-82f5-6f7506fdad21

## 1. 專案目標與適用範圍
以可追蹤、可交接、可繼續修改的方式製作 3D 場景，供動畫、視覺呈現、遊戲或互動用途使用。本專案是「場景製作標準流程」，並非《現實遊戲》任一棟已完成的房屋。每個實際場景須另設唯一場景 ID、尺寸依據、使用情境、版號及主模型來源。
優先原則：劇情／用途正確 > 結構尺寸及動線正確 > 重要家具完整 > 鏡頭可用 > 視覺品質 > 效能與交付。不得用精緻貼圖掩蓋幾何錯誤。

## 2. 十二階段 SOP
| 階段 | 主要工作 | 必須保存的成果／可檢查條件 |
|---|---|---|
| S01 劇情與用途分析 | 拆出場次、人物行為、鏡位、日夜狀態及場景用途；釐清必要與非必要部分 | 場景用途卡、鏡頭與角色需求清單、未知事項 |
| S02 場景需求清單 | 列出空間、門窗樓梯、家具設備、互動道具和必要狀態，區分優先順序 | 場景／房間／物件編號表與完成定義 |
| S03 參考資料蒐集 | 收集平立面、建築尺寸依據、風格、材質及光線參考；記錄來源可信度及授權 | 附來源連結、檔名與觀察摘要的參考索引 |
| S04 平面配置設計 | 訂坐標、單位、建築尺寸、樓層高度、房間比例、家具淨空、角色動線 | 平面／立面或標註草圖、動線圖；**關卡 A：空間與結構方案核定** |
| S05 灰模建立 | 使用簡單幾何建立所有房間與樓層，放入角色尺寸參考物與鏡頭測試位 | 可開啟的灰模候選版、各空間截圖、尺寸核對 |
| S06 主體結構建模 | 精製牆面厚度、地樓板、樓梯、門窗、屋頂及建築構件 | 結構物件清單、重疊／開口／連接處檢查 |
| S07 家具與物件配置 | 大件優先，再配置設備、道具與生活物件；可互動物件須分離 | 物件 ID、擺放座標、用途、狀態清單 |
| S08 模型細節深化 | 修整比例、倒角、接縫、合理厚度、把手、線槽等視覺可見細節 | 近景截圖、幾何缺陷清單；**關卡 B：家具與幾何完整度核定** |
| S09 材質與貼圖 | 設定 PBR 或指定風格材質、UV、貼圖路徑、比例與可重現設定 | 材質清單、貼圖依賴檢查、對照視圖 |
| S10 燈光與場景氛圍 | 同一場景建立白天／夜晚與劇情燈光預設，避免為燈光重複建模 | 各情境燈光預設、相同鏡位對照圖 |
| S11 動畫適用性測試 | 角色走動、上下樓梯、坐下、開門、鏡頭遮擋、穿模、法線、渲染與效能測試 | 測試矩陣、截圖／短影片、失敗項及修復追蹤 |
| S12 驗收與版本交付 | 核對資產完整性、正式候選、匯出格式、貼圖連結、備份與交接 | 版號、來源檔／匯出檔、雜湊、驗收紀錄；**關卡 C：動畫可用性與正式交付核定** |

## 3. 三道關卡
- **關卡 A（S04）空間結構：** 樓層上下對應、房間比例、樓梯連接、門窗位置、角色行走淨空與鏡頭需求均有可核實依據；不符合時不要進入正式精細建模。
- **關卡 B（S08）內容完整：** S02 必要空間及重要家具已在候選模型中出現，位置、尺度、用途、幾何品質符合設計；未完成物件均列於待辦，不可把「有擺放」當作「已完成」。
- **關卡 C（S12）交付：** 材質、燈光、指定角色動作和鏡位已測試，能正常載入輸出檔，來源、依賴與備份齊全；AI 自評通過不等於作者正式核定。

## 4. 每個真實場景必須有的資料欄位
- 場景 ID／名稱／所屬作品或用途／引用劇情場次／擁有者。
- 單位、坐標系、世界原點、比例與測量依據；樓層高度、主要空間尺寸及門窗樓梯尺寸。
- 房間 ID、物件 ID、名稱、所屬樓層／空間、分類、用途、優先級、狀態、父子或依附關係、座標／朝向／尺度。
- 相機 ID、鏡頭用途、角色尺寸與測試動線、可互動狀態；燈光預設及材質／貼圖引用。
- 來源檔、候選版、已採用版、匯出檔、產出位置、格式與引擎版本；必要時附 SHA-256。
- 責任 AI、工作日期、階段、操作與範圍、實際證據、未驗證項、阻礙、下一步。
- 未裁定／衝突／重大變更問題：例如劇情與平面相矛盾、樓層大小不一致，須標記阻礙並要求決策，不得暗中自行變更世界觀。

## 5. AI 接手與修改守則
1. **先讀再改：** 開工先讀工作台專案、最近工作紀錄、場景規格、正式模型來源及版本、開放問題；需要用到原模型幾何時必須實際讀取原檔，僅看到網址不代表已檢查。
2. **任務類型分流：** 新場景從 S01 起；既有場景修改先確認原始資料、影響物件／階段與下游依賴，只重做受影響工作；禁止不經同意整棟重建。
3. **範圍隔離：** 不跨場景覆寫物件，也不把不同集數或作品的設定視為同一份採用版本。
4. **非破壞版控：** 原始模型與正式採用版唯讀保留，修改輸出 `<sceneId>_<version>_candidate`；核定前不能覆蓋 adopted/master。
5. **逐物件核對：** 原 ID 優先，新增物件取得新穩定 ID；對移除、合併、尺寸或位置變化給變更清單與影響評估。
6. **證據與狀態誠實：** 規劃、實作、測試、AI 初驗、作者正式採用各自分開記錄。未實際打開模型、跑測試或閱讀來源，不可聲稱已完成驗收。
7. **失敗可接續：** 工具離線、驗證不足或測試失敗時保存錯誤碼、已完成範圍、未測項與下一步，不臆測成功。
8. **與員工守則一致：** 工作台正式紀錄作為交接依據，與專案外的草稿、聊天或範例不得混淆。

## 7. 設計與實際製作的界線
本文件目前只建立「場景製作流程」和後續資料記錄規範；並未自動生成房屋、家具、貼圖或 GLB，也未代替現存 3D 建模服務操作。開始製作第一個場景前，須先指定場景與來源，再由模型工具實作、保存候選及驗證。
