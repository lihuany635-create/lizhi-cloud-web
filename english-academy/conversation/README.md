# TASK-015｜聊天錯句與單字卡：既有英文學習教室整合候選

**不在正式網站部署；無實際學習資料；不新增第二套教室、資料庫、ChatGPT 單字卡或 Site。**

使用者希望將 ChatGPT 英文朋友對話中發現的錯句與單字，交由他已製作的**立之英文學習教室**紀錄、審核並排入正式單字卡。

## 本候選已提供

- \`ledger.mjs\`：會話層**記憶體**暫存錯句、單字、不可覆寫的人工複習證據；不持久化、不自動標 CEFR。
- \`p6-bridge.mjs\`：把候選錯句轉成既有 P3/P6 的 \`record_language_errors\` 格式；把不熟悉的單字轉成 \`create_card_candidates\` 格式；**不呼叫 MCP、不寫入任何後端**。
- \`tests/\`：合成語句測試候選防重、複習證據、匯出入驗證和 P3/P6 轉換。

> 這只是已有 P3/P6 正式架構的資料契約擴展準備，不得將 \`p6-bridge\` 視為可獨立提供登入、正式卡片或 FSRS 服務的後端。

## 正式整合路徑（仍未完成）

1. 真實 Site-to-Google owner 身分綁定，並在**受信任的後端**確認學習來源 session、明確資料授權範圍；不可讓聊天模型宣稱有權。
2. 既有 P6 資料庫 \`english_p6_ingest_batch\` 交易經正式批准部署，提供 owner-isolated 錯誤歷程和待審候選卡；不可另建平行表。
3. 既有網站候選卡審核畫面依使用者明確批准，經原子 RPC 升格正式單字卡，再使用原 P2 FSRS-7 / P4 適性複習。
4. 當次 ChatGPT 不得擅自判定正式能力。錯句修正與單字釋義須先人工或可信程序覆核，複習 evidence 保留。
5. 保留原有 Site 的 MCP 工具、Side、工作台、立剪與照片功能；獨立資安、實機、雙裝置同步與 G01～G12 驗證不可跳過。

目前正式網站僅有 **七題型＋14 題靜態體驗版**，沒有持久化的單字卡與 ChatGPT MCP。正式 Supabase 中未見 \`english_*\` 學習表。因此無法將目前對話的真實語句聲稱已保存在網站。

**使用者真實語料不得提交到公開 GitHub。** 單字及錯句內容只在獲授權的正式私人系統中保存；本開發分支使用非真實學習者的虛構示例。

驗收狀態：候選程式／自測；未部署、未寫正式資料，待 P8-B G01～G12 全數正式驗收與使用者分項批准。
